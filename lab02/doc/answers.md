## 2-2. 가. 파일 탐색기
2-2. 각 화면에서 실제로 작업하기
가. 파일탐색기-폴더 만들기
터미널에서 'ls lab02'를 실행한 결과, 'data', 'doc', 'src', 'test'폴더가 확인되었다.
파일탐색기에서 만든 폴더가 실제 디렉터리에서 생성되어 터미널에서도 확인할 수 있다는 것을 알 수 있다.

## 2-2. 나. 검색
나. 검색 - 단어 세기
-'Alice' 검색, Aa 끔 : 2개 파일에서 400개 결과
-'Alice' 검색, Aa 켬 : 1개 파일에서 399개 결과
-'alice' 검색, ab 끔 : 2개 파일에서 400개 결과
-'alice' 검색 , ab 켬 : 2개 파일에서 399개 결과
-터미널에서 'grep -o -i "Alice" lab02/data/alice.txt | wc -1' 실행 결과 : 399개
검색 화면에서는 'Alice'를 대소문자 구분 없이 검색했을 때 400개의 결과가 나왔지만, 터미널에서는 399개가 나와 두 숫자가 다르다. 검색 화면은 프로젝트 전체의 2개 파일을 대상으로 검색했지만, 터미널 명령어는 'lab02/data/alice.txt' 한 파일만 대상으로 검색했기 때문에 결과에 차이가 발생한 것으로 보인다.

## 2-2. 다. 소스 제어
다. 소스 제어 - 터미널 없이 커밋하기
소스 제어 아이콘에 표시된 숫자 3은 현재 Git에서 변경된 파일이 3개 있다는 것을 의미한다.
'git log -1'을 실행한 결과 :
```text
commit af76615b5c9db6e539f8d9dd17c6ced24486b6ac (HEAD -> main, origin/main, origin/HEAD)
Author: park siyeon <20221244@sungshin.ac.kr>
Date:   Tue Sep 8 22:48:15 2026 +0000

    complete answers
```

터미널을 이용하는 것보다 소스 제어 화면을 이용하여 커밋하는 것이 더 편했다. 변경된 파일을 화면에서 바로 확인할 수 있고, 명령어를 직접 입력하지 않아도 스테이징, 커밋, 동기화 과정을 순서대로 수행할 수 있기 때문이다.
